# TTC status data

The status backend reads TTC's official route-alert endpoint at `https://www.ttc.ca/ttcapi/routedetail/getallroutesandstopsalerts`, with the official GTFS-Realtime alert feed as a bounded fallback.

`getTtcStatus()` returns `{ state, fetchedAt, sourceUpdatedAtRaw, sourceUpdatedAt?, sourceUrl, lines, alerts }`. `fetchedAt` records when this service received the response and is the freshness signal for a successful bounded request. `sourceUpdatedAtRaw` preserves the TTC's publisher-update text. `sourceUpdatedAt` appears only when that text contains an explicit timezone and can therefore be represented honestly as an instant. The publisher-update text is a content-change hint, not a heartbeat: quiet service can legitimately leave it unchanged for hours. The five current rapid-transit lines are Line 1 Yonge-University (`#f4c300`), Line 2 Bloor-Danforth (`#1d7a3a`), Line 4 Sheppard (`#6a1b9a`), Line 5 Eglinton (`#8a1538`), and Line 6 Finch West (`#00838f`).

The TTC payload contains `routeAlerts` alongside other categories such as accessibility and stop alerts. It is not treated as a subway-only field. An active alert with an explicit rapid-transit route disrupts only that line. A TTC website alert with no route or mode is network-wide and appears on every rapid-transit line. In the GTFS-Realtime fallback, only an agency-only selector with no route, route type, trip, stop, or direction restriction is network-wide; a constrained selector without a safe route association remains unconfirmed. TTC notices whose `effectDesc` is `Regular service` stay visible in the aggregate alerts but do not mark a line disrupted. A failed refresh makes all line states `unknown`; cached data is returned as `stale` after the 45-second cache window, and stale data never yields a `good` or `disrupted` line state. Requests use an eight-second abort deadline, refuse redirects, and cap both response bytes, alert count, and per-alert route references.

The parser accepts the GTFS-Realtime protobuf wire format directly, bounds payload size and entity count, sanitizes provider text, and applies an 8 second request deadline. It retains only bounded alert fields and never logs the upstream response.

See [alerts beside a journey leg](leg-alerts.md) for how a leg selects the alerts that apply to it, and [TTC disruption route groups](route-groups.md) for the explicit source-metadata and official-catalog rules that separate rapid transit, streetcar, bus, network-wide, and unclassified alerts.
